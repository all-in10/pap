Resumo

O presente relatório de PAP descreve o desenvolvimento do TeamCore, uma aplicação web de gestão de Recursos Humanos (RH) desenvolvida com o objetivo de simplificar e centralizar processos críticos de gestão de pessoal. O projeto aborda a necessidade de uma ferramenta intuitiva e eficiente que permita às organizações gerenciar dados de funcionários, contratos, horários de trabalho e períodos de licença de forma integrada.

O TeamCore foi desenvolvido utilizando a framework Laravel 12 com Filament 3 como administrador de painel, proporcionando uma interface moderna baseada em componentes reutilizáveis. A arquitetura foi concebida para suportar múltiplos painéis de acesso (Administrador, Recursos Humanos, Funcionário) com segregação de dados e permissões específicas por perfil de utilizador.

A aplicação implementa funcionalidades essenciais para gestão de RH, incluindo: centralização de dados de funcionários, departamentos, cargos e contratos; registo de presença e cálculo automático de horas trabalhadas com suporte a pausas/almoços; geração automática de documentos (contratos em PDF); e gestão de pedidos de licenças/férias com fluxos de aprovação.

O processo de desenvolvimento adotou uma metodologia iterativa, com ciclos bissemanais de implementação, testes e validação. A aplicação foi testada através de suite de testes automatizados (Pest/PHPUnit), cobrindo cenários de autenticação, autorização, regras de negócio e integrações principais. A interface foi totalmente localizada para Português de Portugal (PT-PT), garantindo uma experiência de utilizador adequada ao mercado ibérico.

Até à data de redação deste relatório (10 de Fevereiro de 2026), o projeto atingiu um estado funcional e testado, com funcionalidades core implementadas e validadas. Funcionalidades adicionais estão planeadas para fases futuras.

Arquitetura e Estrutura

A aplicação foi estruturada em três painéis principais, cada um servindo um papel específico de utilizador:

1. **Painel Admin (/admin):** Acessível apenas a utilizadores com role 'ADMIN', permite gestão completa de todos os recursos: utilizadores, funcionários, contratos, departamentos, designações, tipos de contrato, países, estados, cidades, benefícios e categorias de licença.

2. **Painel HR (/hr):** Acessível apenas a utilizadores com role 'HR', permite gestão de recursos específicos de RH: funcionários, contratos, departamentos, designações, licenças, categorias de licença, benefícios, registos de trabalho, banco de horas e presença.

3. **Painel Funcionário (/employee):** Acessível apenas a utilizadores com role 'EMPLOYEE', oferece funcionalidades limitadas com foco no próprio funcionário: visualização de informações pessoais e profissionais, saldo de banco de horas, e gestão de pedidos de licença.

A segregação é aplicada através de:
- **Middleware de autenticação:** Garante que apenas utilizadores autenticados acedem os painéis.
- **Middleware de verificação de role:** Redireciona utilizadores para o painel apropriado e bloqueia acesso não autorizado.
- **Políticas de autorização:** Definidas no AppServiceProvider e aplicadas ao nível do modelo, verificando permissões em operações CRUD.

Funcionalidades Implementadas

### 1. Gestão de Funcionários
- Registo completo com dados pessoais (nome, data de nascimento, contacto) e profissionais (departamento, cargo, salário).
- Automatização na criação de funcionário: criação automática de conta de utilizador, contrato padrão e banco de horas.
- Isolamento de dados ao nível do modelo: funcionários apenas veem seus próprios dados no painel Employee.

### 2. Gestão de Contratos
- Criação, edição e aprovação de contratos com tipos configuráveis (tempo indeterminado, termo certo, etc.).
- Geração automática de contratos em PDF (barryvdh/laravel-dompdf) com dados atualizados do funcionário.
- Histórico de contratos por funcionário.

### 3. Registo de Presença e Banco de Horas
- Registo de horas de trabalho com suporte a pausas/almoços (campos 'break_start' e 'break_end').
- Cálculo automático de horas trabalhadas excluindo tempo de pausa.
- Atualização automática do saldo de banco de horas após cada registo validado.
- Widget EmployeeInfoWidget que mostra o saldo atual ao funcionário.

### 4. Gestão de Licenças/Férias
- Sistema de pedidos de licença com categorias configuráveis (férias, doença, licença paternidade, etc.).
- Estados de pedido (pendente, aprovado, recusado) com fluxo de aprovação.
- Contagem automática de pedidos pendentes para cada funcionário.
- Acesso de funcionários ao portal para submeter novos pedidos.

### 5. Autenticação e Controlo de Acesso
- Autenticação baseada em sessão com Laravel default (guard 'web').
- Três roles de utilizador: ADMIN, HR, EMPLOYEE.
- Senha padrão obrigatória para novos utilizadores com flag 'must_change_password'.
- Rota dedicada para mudança de senha (UserPasswordController).

### 6. Localização (i18n)
- Interface completamente traduzida para Português de Portugal.
- Labels de recursos, formulários, colunas de tabelas e mensagens de validação localizadas.
- Implementação através de labels diretos nos recursos Filament (navigationLabel, pluralModelLabel, etc.).

### 7. Widget de Informações do Funcionário
- Widget customizado (EmployeeInfoWidget) exibido no dashboard do painel Employee.
- Mostra dados pessoais, saldo de banco de horas, contagem de pedidos de licença pendentes.
- Botões de ação rápida para solicitar licença ou ver histórico de pedidos.

### 8. Estatísticas e Dashboard
- Widget GeneralStats que exibe 4 métricas principais no painel Admin e HR:
  - Total de utilizadores
  - Total de colaboradores
  - Contratos ativos
  - Licenças pendentes

### 9. Testes e Validação
- Suite de testes com Pest/PHPUnit cobrindo:
  - Testes de permissões (PermissionsTest) - validação de acesso por role
  - Testes de middleware (PanelRoleMiddlewareTest) - proteção de painéis
  - Testes de política de senha (PasswordPolicyTest)
  - Testes de funcionalidade geral (Feature/ExampleTest, Unit/ExampleTest)
- Todos os testes passam com sucesso localmente.

Decisões Técnicas Relevantes

1. **Filament como painel administrativo:** Escolhido pela capacidade de gerar rapidamente interfaces CRUD, suporte a múltiplos painéis e policies nativas.

2. **Políticas Eloquent ao invés de gates globais:** Implementadas no AppServiceProvider para validação no nível do modelo, proporcionando maior granularidade e reusability.

3. **Isolamento de dados via relações:** Modelos implementam relações apropriadas para filtrar dados automaticamente.

4. **Testes com Pest:** Escolhido pela sintaxe mais limpa e expressiva comparada a PHPUnit puro.

5. **PDF com DomPDF:** Escolhido pela simplicidade de integração com Laravel e suporte a HTML/CSS.
